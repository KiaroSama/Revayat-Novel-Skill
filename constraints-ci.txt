# What CI installs. NOT what a reader installs.
#
# `skills/revayat-novel/requirements.txt` states minimum versions on purpose:
# this is a skill people copy into their own agent directory and run against
# whatever interpreter and wheels they already have, so narrowing those floors
# would narrow the set of machines it works on. `dependabot.yml` disables pip
# version updates for that reason.
#
# The side effect was not decided: eighteen CI jobs resolved those floors
# freshly on every run, so a release by any of six upstreams could turn a green
# build red on a commit that changed nothing, and the failure arrived attached
# to whoever pushed next. This project already learned that on `ruff`, whose
# default rule set widened from 0 findings to 196 between two releases — which
# is why the lint step pins it.
#
# pymupdf is the one that matters most: it is the PDF reader, the page geometry,
# the image extraction and the render readback, and test_readers.py,
# test_renderqa.py, test_docqa.py and test_pagerun.py all assert on numbers it
# produces.
#
# Dispatch CI on the exact revision whenever this set changes. Results from
# earlier pins do not verify a new set.
#
# The optional tools `ocrmypdf` and `pywin32` are declared separately. Their
# integration workflows install them only where needed.
#
# Dependabot groups updates to these pins for review.
# Dependabot does update this file. Verified against dependabot-core rather than
# assumed: its pip fetcher takes every `.txt` whose lines all parse as
# requirements or comments, which this does, so the `ci-constraints` group in
# dependabot.yml is real.
#
# GitHub's **dependency graph** is a different system and does not list it — the
# graph recognises `requirements.txt` by name, and of the manifests it reports for
# this repository, this is not one. So `dependency-review.yml`, which reviews what
# the graph says a pull request changed, sees nothing when a pin here moves. The
# advisory question is covered anyway, from the other side: dependency-audit.yml
# resolves this exact set weekly and audits it. Nothing here is silently
# unreviewed; it is reviewed by the scheduled scan rather than on the pull request.
